# 2026-03-23 发布 1.0.1 与 macOS 构建工作流

## 目标

- 发布版本 `1.0.1`
- 增加 GitHub Actions
- 自动构建 macOS 客户端

## 本次实现

### 1. 版本号升级

- `package.json` 版本升级到 `1.0.1`
- `package-lock.json` 同步升级到 `1.0.1`

### 2. GitHub Actions 工作流

新增工作流：

- `.github/workflows/release-macos.yml`

触发方式：

- 手动触发 `workflow_dispatch`
- 推送 tag 时自动触发，匹配：
  - `v*`

工作流内容：

- `npm ci`
- `npm run lint`
- `npm run typecheck`
- `npm test`
- `npx electron-builder --mac zip dmg --publish never`

产物处理：

- 上传 `dist/*.dmg`
- 上传 `dist/*.zip`
- 上传 `dist/*.blockmap`

如果是 tag 触发：

- 自动发布到 GitHub Release
- 自动生成 Release Notes

### 4. Release 失败修复

首次触发 `v1.0.1` tag 工作流时，`electron-builder` 因为 `package.json` 中的仓库地址是本地代理 URL，且 tag 构建会隐式触发发布流程，导致无法识别 GitHub 仓库并构建失败。

本次修复：

- 将 `repository.url` 改为真实 GitHub 仓库地址
- 增加 `build.publish.github` 配置，明确 owner 和 repo
- 将构建命令改为 `--publish never`
- 由后续的 `softprops/action-gh-release` 单独负责发布 Release 资产

### 3. 签名策略

当前工作流默认关闭自动证书发现：

- `CSC_IDENTITY_AUTO_DISCOVERY=false`

这样可以先稳定产出 unsigned 的 macOS 包，后续需要签名时再补证书与 notarization 配置。
