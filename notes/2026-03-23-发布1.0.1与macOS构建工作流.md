# 2026-03-23 发布 1.0.1 与 macOS 构建工作流

## 目标

- 发布版本 `1.0.1`
- 增加 GitHub Actions
- 自动构建 macOS 客户端

## 本次实现

### 1. 版本号升级

- `package.json` 版本升级到 `1.0.1`
- `package-lock.json` 同步升级到 `1.0.1`

### 2. GitHub Actions 工作流

新增工作流：

- `.github/workflows/release-macos.yml`
- `.github/workflows/test-macos.yml`

触发方式：

- 手动触发 `workflow_dispatch`
- 推送 tag 时自动触发，匹配：
  - `v*`

测试包工作流：

- 仅支持手动触发 `workflow_dispatch`
- 只上传 Actions Artifact
- 不创建 GitHub Release
- 适合你自己快速下载自测

工作流内容：

- `npm ci`
- `npm run lint`
- `npm run typecheck`
- `npm test`
- `npx electron-builder --mac zip dmg --publish never`

产物处理：

- 上传 `dist/*.dmg`
- 上传 `dist/*.zip`
- 上传 `dist/*.blockmap`

如果是 tag 触发：

- 自动发布到 GitHub Release
- 自动生成 Release Notes

### 4. Release 失败修复

首次触发 `v1.0.1` tag 工作流时，`electron-builder` 因为 `package.json` 中的仓库地址是本地代理 URL，且 tag 构建会隐式触发发布流程，导致无法识别 GitHub 仓库并构建失败。

本次修复：

- 将 `repository.url` 改为真实 GitHub 仓库地址
- 增加 `build.publish.github` 配置，明确 owner 和 repo
- 将构建命令改为 `--publish never`
- 由后续的 `softprops/action-gh-release` 单独负责发布 Release 资产

### 5. GitHub Actions Node 24 兼容

GitHub Actions 已开始告警 Node 20 JavaScript Actions 运行时弃用。本次同步升级工作流，减少后续在 2026-06-02 之后的兼容风险：

- `actions/checkout` 升级到 `v6`
- `actions/setup-node` 升级到 `v6`
- `actions/upload-artifact` 升级到 `v6`
- `setup-node` 的 `node-version` 改为 `24`
- 在 job 级别添加 `FORCE_JAVASCRIPT_ACTIONS_TO_NODE24=true`

说明：

- `softprops/action-gh-release@v2` 仍保持不变
- 通过 `FORCE_JAVASCRIPT_ACTIONS_TO_NODE24` 提前用 Node 24 运行，避免继续出现 Node 20 弃用告警

### 6. macOS 下载包不可直接打开问题

排查结果：

- Release 上的 `zip` 和 `dmg` 文件本身是完整的
- `unzip -t` 校验通过
- `hdiutil verify` 校验通过

根因是分发安全，而不是包损坏：

- 当前 CI 未配置 Apple Developer ID 证书
- 当前 CI 未配置 Apple notarization 凭据
- 因此产物只是 ad-hoc 签名，下载到其他 macOS 机器上会被 Gatekeeper 拦截

本次补充：

- 新增 `scripts/notarize.cjs`
- 新增 `assets/entitlements.mac.plist`
- `electron-builder` 增加 `afterSign`
- `mac` 构建增加 `hardenedRuntime`、`entitlements`、`entitlementsInherit`
- 工作流接入以下 secrets：
  - `APPLE_CERTIFICATE_P12`
  - `APPLE_CERTIFICATE_PASSWORD`
  - `APPLE_ID`
  - `APPLE_APP_SPECIFIC_PASSWORD`
  - `APPLE_TEAM_ID`

说明：

- 如果上述 secrets 缺失，工作流仍可构建，但产物仍会是未签名/未公证状态
- 配齐 secrets 后，后续 Release 将自动尝试签名并公证

### 3. 签名策略

当前工作流默认关闭自动证书发现：

- `CSC_IDENTITY_AUTO_DISCOVERY=false`

这样可以先稳定产出 unsigned 的 macOS 包，后续需要签名时再补证书与 notarization 配置。
